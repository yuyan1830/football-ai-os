==================================================
一、项目背景
==================================================

当前 Football AI OS 项目经过框架建设后，发现：

原设计：

90_COMMON_SERVICES
        ↓
统一公共服务层


实际运行：

00_System_OS
└──01_DATA_LAYER
    └──core

已经承担系统核心服务。


因此调整架构策略。


==================================================
二、最终架构原则
==================================================


不推倒重建。

不采用：

core
 ↓
全部迁移
 ↓
common_services


原因：

1. 数据层已经依赖core
2. 当前系统运行稳定
3. 大规模迁移风险较高
4. 会影响已有模块


采用：

Core Upgrade Fusion Strategy

核心升级融合策略。


即：

现有core
+
90_COMMON_SERVICES优秀能力

↓

升级后的统一核心服务。

==================================================
六、升级规则
==================================================


规则1：

保持旧接口。


例如：

from core.logger import xxx


继续有效。


不大量修改已有业务代码。



------------------------------


规则2：

内部升级。


例如：

旧：

core/logger.py


升级：

core/logger/

├── logger.py
├── formatter.py
├── handlers.py
└── log_config.json



------------------------------


规则3：

先保证运行稳定。

再优化结构。

禁止为了架构美观破坏运行系统。
