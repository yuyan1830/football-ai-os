# PART 1 — AI 通用行为规则
==================================================

这些规则适用于本项目所有任务。

原则：

非简单任务优先谨慎，不追求盲目速度。
任何不确定情况必须明确说明。


--------------------------------------------------
## Rule 1 — 编码前先思考
--------------------------------------------------

执行任何修改前：

必须：

1. 明确目标
2. 说明假设
3. 分析影响范围
4. 判断是否存在已有能力


如果存在不确定：

禁止猜测。

必须提出问题。


--------------------------------------------------
## Rule 2 — 简单优先
--------------------------------------------------

使用解决问题所需的最小方案。

禁止：

- 过度设计
- 无需求新增功能
- 创建重复抽象


优先保持系统稳定。


--------------------------------------------------
## Rule 3 — 精准修改
--------------------------------------------------

只修改必要文件。

禁止：

- 顺便重构
- 修改无关代码
- 改变已有设计风格


--------------------------------------------------
## Rule 4 — 目标驱动执行
--------------------------------------------------

所有任务必须定义：

成功标准。

执行：

计划
→ 修改
→ 测试
→ 验证


--------------------------------------------------
## Rule 5 — 使用AI进行判断，不替代确定性代码
--------------------------------------------------

AI用于：

- 分析
- 设计
- 判断
- 总结


确定性任务优先使用代码完成。


--------------------------------------------------
## Rule 6 — 状态检查
--------------------------------------------------

重要步骤完成后必须报告：

已完成：

已验证：

剩余：

风险：


禁止在未知状态继续执行。


--------------------------------------------------
## Rule 7 — 冲突处理
--------------------------------------------------

如果发现：

旧方案与新方案冲突。


必须：

选择依据明确的方案。

禁止简单混合。


--------------------------------------------------
## Rule 8 — 修改前阅读
--------------------------------------------------

修改任何代码前必须：

读取：

- 当前文件
- 调用关系
- 依赖模块
- 相关配置


禁止未阅读直接修改。


--------------------------------------------------
## Rule 9 — 测试验证意图
--------------------------------------------------

测试必须验证：

业务目标。

不仅验证：

代码是否运行。


--------------------------------------------------
## Rule 10 — 检查点机制
--------------------------------------------------

重大操作必须建立Checkpoint。


必须记录：

操作内容

影响范围

验证结果


--------------------------------------------------
## Rule 11 — 遵循项目规范
--------------------------------------------------

项目现有规范：

优先级高于个人偏好。


禁止私自建立新的架构模式。


--------------------------------------------------
## Rule 12 — 明确失败
--------------------------------------------------

禁止：

虚假完成。

禁止：

跳过测试后声明通过。


所有风险必须公开。
